## 3′.1 为什么这样就够回答「接受率会不会 > 0」

真正的接受率需要跑完整投机循环：稀疏草稿 → 密集验证。而草稿必须跑一次**稀疏注意力前向**，
这需要自建 sparse KV 前向 —— 那是几周的工程量。

但它的**前置条件**可以便宜且精确地测出来：

> STD 保留的 top-K 视觉位置，**是否承载了「预测下一个 token 的那一行」所依赖的注意力质量？**
>
> 如果答案是「只承载 ~25%」，那么基于这些位置的稀疏草稿**在原理上就与密集模型看到的不是同一批 KV**，
> 它提出的 token 会被密集验证大量拒绝 —— 这正是 `accept_rate = 0.0` 的机制。

同时本探针检验一个**尖锐的假设**：

> `build_sparse_selection` 的评分是 `grouped.sum(dim=(1, 2))` ——
> **对所有 query 位置求和**。但 token n+1 只取决于**最后一个 query 行**。
> 所以「全 query 求和」的判据可能选出与下一个 token 无关的位置，同时漏掉真正关键的。

## 3′.2 结果（4 帧，prompt=2422，视频 token=2392，text 行=32，**8 层**）

```
    K |  STD all-query mass_recall |  last-query oracle |  std overlap
   16 |             0.0824 +/- 0.0430 |             0.4668 |       0.2578
   32 |             0.1083 +/- 0.0405 |             0.5595 |       0.2695
   64 |             0.1461 +/- 0.0405 |             0.6520 |       0.2676
  128 |             0.1761 +/- 0.0463 |             0.7363 |       0.2939
  256 |             0.2464 +/- 0.0771 |             0.8133 |       0.3398
  512 |             0.3086 +/- 0.0891 |             0.8841 |       0.4199
```

**定义**
- `mass_recall`：在**最后一行自己的**注意力分布上，被选中的 top-K 位置所占的视觉注意力质量比。
- `last-query oracle`：同样测最后一行质量，但选择用「只按最后一行打分」（理论上限参考）。
- `std overlap`：STD 选出的集合与 last-query oracle 集合的**重合率**。

---

## 3′.3 两个结论

### 结论 1（主）：STD 的评分判据与「预测下一个 token」错位

在**同样的 K** 下：

| K | STD 判据保住的最后一行注意力质量 | last-query 判据 | 倍数 |
|---:|---:|---:|---:|
| 64 | 14.6% | 65.2% | **4.5×** |
| 256 | **24.6%** | **81.3%** | **3.3×** |
| 512 | 30.9% | 88.4% | 2.9× |

且 STD 选出的集合与 last-query oracle 的**重合率仅 26%–42%**。

**即：STD 的 `sum over all query positions` 把「哪些视觉位置对整段文本重要」当成了
「哪些视觉位置对下一个 token 重要」。这两件事不是一回事。**
在 K=256 时，它只保住了下一个 token 真正依赖的注意力质量的 **约四分之一**。

> **这就是 `accept_rate = 0.0` 的机制性解释**：稀疏草稿看到的 KV 集合与密集模型用的集合
> 大量不重叠，因此它提出的 token 与密集模型的 argmax 系统性不一致。

### 结论 2：即使修好判据，K 也必须足够大

用「只按最后一行打分」这个**理论上限参考**，要保住 80% 的视觉注意力质量，
需要 **K ≈ 256**（占 2392 个视频 token 的 **10.7%**）。
这说明稀疏性本身在**第 0 层附近的注意力是弥散的**（视频 token 只分到该行约 23% 的质量）。

## 3′.4 这能不能直接断定接受率为 0？

**不能，必须说清楚边界。** 本探针测的是**前置条件（注意力质量保真度）**，不是接受率本身。
严格的因果链是：

```
选中位置只保住 ~25% 的相关注意力质量
  → 稀疏前向的 hidden state 与密集前向差异显著
  → argmax 经常不同
  → 接受率接近 0
```

中间两步是**统计性的，不是等价的**。所以正确表述是：

> **「有强证据表明接受率会接近 0，但接受率本身仍未实测。」**

要把它变成实测，仍需一次稀疏前向。**这一点没有被掩盖。**

### ❌ 已作废的张力段（2026-09-26 更正）

本节原写「`PROGRESS.md` §19 记录静态 STD 接受率 0.966–1.000」。**两处错误，均已在
`docs/vllm-std/17-section19-criterion.md` 中查明并更正：**

1. **章节归属错**：那些数字在 **§17**（`PROGRESS.md:642` 起的动态路由节，表在 `:690-698`），
   **不在 §19**（`PROGRESS.md:1514`，讲的是 `c_s`/draft-layers/compile 三个 decode 开关，无接受率表）。
2. **更严重的是：§17 的静态 STD 用的判据与本探针假设的「全 query 求和」逐字相同**
   （`src/std_repro/std_qwen25vl.py:239`，调用点 `:1224`，产出者
   `scripts/benchmark_a100_dynamic.py:330`），**而它的实测接受率是 0.507–1.000**。

**因此本探针的推测被直接观测量否证。**
§3′.3 的结论只应被理解为「本探针构造的代理指标（最后一行注意力质量保真度）
与接受率之间没有可靠映射」，**不应被理解为 STD 判据有缺陷**。

**A1（修判据）已判定不执行**，理由见 `docs/vllm-std/18-a1-decision.md`。
